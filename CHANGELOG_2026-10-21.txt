1. 사용자에게 달라지는 동작

매출 추이 답변과 그래프
- 선택 기업의 현재 승인 원장에서 처리월별 청구 공급가액과 감액을 서버가 합산한다.
- 지표는 '제공된 계약 원장 기준 순공급가액(VAT 제외)'이며 입금액·회사 전체 매출로 단정하지 않는다.
- 같은 계산 결과를 답변과 시각화 데이터에 함께 저장한다.
- '이 내용을 그래프로 보여줘'와 긴 한국어 요청, '막대그래프', '표' 같은 표현을 처리한다.
- 새로운 기업·기간·항목 조건을 추가한 요청은 이전 답변을 그대로 재사용하지 않는다.
- 시각화 자료 탭에서 그래프·표, 원 답변·근거, 원 대화 이동, CSV/SVG 다운로드를 제공한다.
- 지원하지 않는 표현 또는 데이터 조건이 맞지 않는 표현은 이유와 함께 표로 제공한다.

인용과 부분 답변
- 일반 문서 답변 전에 질문의 독립 요청 항목을 분리한다.
- 필수 item_N별로 supported / missing / mismatch / conflict를 판정한다.
- 모델은 유효한 원문 정수 번호만 선택한다. 서버가 문서·줄 ID와 인용문을 복원한다.
- 인용 연결 실패(citation_error), 자료 부족(missing), 검색 서비스 실패를 구분한다.
- 하나를 모른다고 다른 정상 항목을 버리지 않고 partial·item_results·reason_code로 저장한다.
- 원문에 명시된 0건·없음 등 실제 값은 그 표현만으로 자료 부족 처리하지 않는다.
- 인용의 형식적 일치는 의미적 정답을 보장하지 않으므로 기존 항목·대상·기간·조건 검사를 유지한다.

선택 문서와 일반 대화, 회사 선택
- 팀원 main(ad94df8)의 선택 문서 맥락 안내와 경로 계획 방식을 반영했다.
- 문서를 선택해도 인사는 일반 대화로, 최신 정보는 기존 검증된 웹 경로로 보낸다.
- 회사 자료를 묻는 질문은 선택 회사와 문서 범위를 유지한다.
- 팀원 UI처럼 회사 이름 위치에서 회사를 선택한다.
- 회사 변경 시 선택 문서·프로젝트·이전 대화 주소를 정리하고 늦은 이전 회사 응답을 차단한다.
- 탭별 회사 선택 저장은 유지한다.

4. 속도·비용·남은 한계

- 12문항 응답시간 중앙값: 4.114초 → 4.398초.
- 일반 문서 질문 6개 중앙값: 4.499초 → 6.862초.
- 질문 항목 분리 호출이 추가됐다. 단일 실행의 네트워크·API 지연 영향도 있으므로
  증가분 전부를 특정 단계의 원인으로 확정하지 않는다.
- 앱 내부 추정 비용: 74.72원 → 63.43원. 청구서 기준이 아니고 개별 토큰 원장 기록이
  없어 비용이 항상 줄었다고 주장하지 않는다. 실제 모델 호출 수와 앱 사용량 행 수도 다르다.
- 질문 분리와 원문 의미 판정에는 모델 오류가 남을 수 있다. 새로운 독립 질문 평가가 필요하다.
- 기존 대화의 과거 잘못된 상태를 소급 수정하지 않았다. 새 질문부터 적용된다.
- 현재 데모 인증 구조는 유지했다. 회사 범위 검사는 다중 사용자 로그인 인증을 대신하지 않는다.

5. 보존 및 실행

로컬 원문 1,000개, 문서·자산·색인 연결·사업 지표·세부 지표를 변경 전후 해시로 확인했다.
포트 8000과 compose.yaml의 127.0.0.1:8000:8000 매핑을 유지했다.
DB 변경은 CREATE TABLE IF NOT EXISTS visualizations 및 인덱스 추가다. 기존 테이블을 삭제하거나
문서를 재색인하지 않는다. 기존 Dify 색인을 재사용한다.

코드는 Git에 올리지만 .env, 실제 data/, DB, API 키, 실행 로그는 올리지 않는다.
따라서 팀원이 clone하는 것만으로 기존 1,000개 문서·Dify 지식베이스가 생기지는 않는다.
기존 로컬 .env/data/를 보존하고 각자 접근 권한이 있는 Dify 연결을 준비한다.

실행(저장소 루트):
  uv sync
  uv run uvicorn psm.api:app --reload --host 127.0.0.1 --port 8000

Docker 실행:
  docker compose up -d --build

이미 로컬 Python 서버가 8000을 쓰고 있다면 같은 포트의 Docker 앱을 동시에 시작하지 않는다.
위 두 실행 방법 중 하나를 사용한다. Dify는 별도로 실행되는 기존 서비스다.
새 설치에서만 .env.example을 참고해 .env를 준비하며, 기존 .env를 덮어쓰지 않는다.

6. 자동 검사

검증된 앱 코드의 오프라인 Python 888건·JavaScript 48건 통과.
업로드할 Git 파일만 별도 폴더로 추출한 상태에서도 Python 888건·JavaScript 48건 통과를 확인했다.
별도 eval 파일이 없어 1건 건너뜀, Windows 심볼릭 링크 생성 권한 제약으로 기존 2건 제외.
해당 제외를 통과로 계산하지 않았다. 6개 Pydantic 경고는 잘못된 출력 주입 방어 검사에서 발생했다.
자동 검사 수치는 실제 AI 정답률과 별도다.

일반 실행:
  uv run python tests/run_offline.py tests -q
  node --test tests/js/*.test.mjs

같은 Windows 권한 제약이 있는 환경의 재현 명령:
  uv run python tests/run_offline.py tests -q -k "not symlinks_pointing_outside_the_folder_are_never_indexed and not symlinked_subfolder_is_skipped"

tests/run_offline.py는 실제 HTTP 전송을 차단한다. 실제 /api/ask 또는
scripts/evaluate_sales_visualizations.py의 실행 모드는 OpenAI 사용료와 새 대화·시각화 저장이 발생한다.
이번 GitHub 업로드 준비에서는 유료 실측을 다시 실행하지 않는다.
