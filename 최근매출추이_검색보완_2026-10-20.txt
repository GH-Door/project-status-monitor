최근 매출 추이 질문 보완 / 2026-10-20

확인된 원인
저장된 대화 22~25에서 같은 뜻의 질문이 성공/자료 부족으로 달라졌다.
현재 시각화 변경의 요청 감지 로직은 “우리 회사 최근 매출 추이에 대해서 알려줘”를 시각화 요청으로 분류하지 않는다.
실패한 질문은 기존 RAG 검색과 항목별 근거 검사를 거쳤다.

수정 전 실제 Dify 검색 비교 (라온공간워크스)
- “우리 회사 매출 추이 좀 알려줄래?”: 상위 8개 중 매출정산원장 6개.
- “우리 회사 최근 매출 추이에 대해서 알려줘”: 상위 8개 모두 사업계획. 매출정산원장 0개.
말투 차이로 검색 순위가 달라져, 매출 수치가 있는 원문이 답변 모델에 전달되지 않았다.
따라서 이 사례는 근거 검사가 매출을 무조건 거부한 문제가 아니라 검색 누락이었다.

변경
1. retrieval_support.py / rag.py
   매출 추이·월별·최근 매출 질문에는 같은 기업의 색인 완료 매출 원장/보고 자료를 메타데이터로 보완한다.
   기본 8개 근거 중 최대 6개를 매출 자료로 보완하고 나머지는 기존 검색 근거를 유지한다.
   선택 문서 범위, 기업 소속, 색인 상태, 현재 승인 상태를 확인한다.
   여러 기업이 섞인 원본 폴더는 회사가 명확하지 않으면 이 보완 단계에서 임의 합산하지 않는다.
   전체 문서 검색/등록/색인은 바꾸지 않으며, 기존 항목별 근거 검사를 그대로 적용한다.

2. llm.py
   프롬프트 버전: ko-item-evidence-v5-sales-periods-20261020
   계약별 최종 정산금액과 월별 추이를 구분한다.
   원장에 처리일별 전표가 있으면 제공된 계약 범위에서 처리월별 공급가액을 설명할 수 있도록 한다.
   감액은 처리월에서 한 번만 차감하고, 이미 감액된 최종 정산금액을 다시 합산하지 않는다.
   “원장 처리일 기준 순공급가액, VAT 제외”를 회계상 매출 인식액/입금액/회사 전체 매출로 바꾸어 부르지 않는다.
   월별 자료가 없으면 확인된 계약별 현황은 답하고 월별 추이의 한계는 따로 설명한다.

3. visualizations.py
   “이거를 대시보드에 그래프로 표현해줄 수 있을까?”
   “이거를 혹시 대시보드에 그래프로 나타낼 수 있어?”
   위 재표현 요청을 문서에서 기능 가능 여부를 묻는 질문으로 보내지 않고 직전 답변의 시각화로 연결한다.
   새 회사/사업/기간/수치 항목을 지정한 질문은 기존 검색 경로를 유지한다.

4. 테스트 통신 차단
   최신 SDK가 사용하는 httpx2 전송 계층도 오프라인 검사에서 차단하도록 보완했다.
   이전 차단기는 httpx만 막았으며, 로그에 테스트용 가짜 키의 인증 실패 요청이 발견되었다.
   이번 최종 회귀 검사는 두 전송 계층을 모두 차단했다.

검증 결과
- 자동 회귀 검사 163건 통과. Ruff 통과.
- 수정 후 실제 검색:
  라온공간워크스의 위 두 질문 모두 동일한 매출정산원장 6개를 확보했다.
  해솔에너지랩 “우리회사 최근 매출 추이를 알려줘”에서도 해당 회사 매출정산원장 6개를 확보했다.
- 기존 원문/색인/사업 지표는 수정하지 않았다. 포트는 8000이다.
- 실제 검색 비교는 했지만 새 GPT 답변 생성이나 정답률 평가는 진행하지 않았다.
  생성 답변의 표현과 계산 정확도는 사용자가 직접 확인한다.

다시 확인하는 순서
http://localhost:8000/ 에서 새로고침한다.
왼쪽에서 라온공간워크스 또는 해솔에너지랩을 선택하고 새 대화를 연다.
“우리 회사 최근 매출 추이에 대해서 알려줘”라고 질문한다.
월별 숫자뿐 아니라 기준/기간/계약 범위/VAT와 감액 처리를 확인한다.
이어서 “이 내용을 그래프로 보여줘”라고 요청하고 시각화 자료 탭에서 표의 값과 비교한다.
예전 보류 답변은 기록으로 보존되며 수정 후 답변으로 자동 덮어쓰지 않는다.
