3. 보존한 데이터와 실행 환경

기존 1,000개 원본, 회사별 문서 연결, 지표와 기존 색인을 유지합니다.
포트 8000을 유지하고 대시보드는 Windows uv/FastAPI로, Dify는 Docker로 실행합니다.
로컬 Dify 인증과 사용 가능한 문서 1,000개를 확인했습니다.
DB 문서/자산 행 2,000개는 원본과 회사별 연결 사본을 포함하며,
Dify 문서를 새로 2,000개 색인했다는 뜻이 아닙니다.

.env, API 키, 문서 원본, SQLite, Dify/Weaviate 볼륨, 실행 로그는 Git에 포함하지 않습니다.
GitHub에서 코드를 받는 것만으로 기존 문서와 DB가 복원되는 것은 아닙니다.
다른 PC/서버에는 별도 환경 설정과 원문/SQLite/Dify PostgreSQL/Weaviate/스토리지/
암호화 키의 일관된 백업·복원이 필요합니다.

Docker Desktop GUI 레지스트리 오류의 영구 해결은 확인하지 않았습니다.
현재는 설치된 백엔드와 로컬 Dify 컨테이너가 동작하며 시작 스크립트에 우회 경로가 있습니다.

6. 핵심 코드 위치

src/psm/library.py, index_reuse.py: 기업 선택/색인 재사용/지표 보존
src/psm/answer_evidence.py: 항목별 결과, 원문 구간 확인/복원
src/psm/llm.py: 한국어 답변/항목 검사 호출/웹·기상 연결
src/psm/rag.py, answering.py: 검색과 문답 경로, 부분 답변 전달
src/psm/web_evidence.py, weather_evidence.py: 웹 원문/기상 API 검사
src/psm/api.py, conversations.py, db.py, schema.sql: 응답/저장/기존 DB 갱신
web/js/chat-messages.js: 답변 및 확인/미확인 사유와 근거 펼침

uv run uvicorn psm.api:app --reload --host 127.0.0.1 --port 8000
